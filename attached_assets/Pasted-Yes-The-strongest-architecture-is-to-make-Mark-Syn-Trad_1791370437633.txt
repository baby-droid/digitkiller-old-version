# 41. Final decision engine

The central algorithm should effectively be:

```text
FOR EACH ACTIVE MARKET:

    LOAD HISTORICAL TICKS

    START LIVE TICK STREAM

    CALCULATE:

        digit_distribution
        parity_distribution
        direction
        digit_runs
        parity_runs
        barrier_regions
        recurrence_patterns
        volatility/noise
        recent_changes

    FOR EACH CONTRACT:

        calculate_contract_score()

        calculate_entry_score()

        calculate_pattern_score()

        calculate_multi_window_confirmation()

        calculate_market_score()

        IF contradiction:
            REJECT

        IF insufficient data:
            REJECT

        IF risk_limit:
            REJECT

        IF score < threshold:
            WATCH

        IF score >= threshold:
            VIRTUAL_VALIDATE

        IF virtual validation fails:
            REJECT

        IF virtual validation passes:
            ARM

        WAIT FOR ENTRY CONDITION

        IF entry condition expires:
            CANCEL

        IF all execution checks pass:
            SEND SIGNAL TO MARK SYN TRADER

        RECEIVE ACK

        REQUEST FRESH PROPOSAL

        VERIFY CONTRACT

        EXECUTE

        MONITOR RESULT

        SEND RESULT BACK TO SIGNAL ENGINE

        UPDATE PATTERN DATABASE
```

## 43. One important implementation/security rule

Do **not** put the Deriv real-account token/PAT in the frontend or inside the Signal page's JavaScript. Deriv's current documentation explicitly recommends keeping tokens server-side; authenticated trading uses an OTP-derived WebSocket URL for the account. ([Deriv API][6])

Use:

```text
Browser
   ↓
Your backend
   ↓
Deriv authentication
   ↓
Authenticated WebSocket
```

rather than:

```text
Browser
   ↓
REAL DERIV TOKEN
```
